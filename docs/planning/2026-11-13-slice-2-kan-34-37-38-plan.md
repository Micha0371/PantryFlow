# Slice 2 follow-ups: announced form errors, named stale add errors, one add screen per tap — plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (recommended here) or superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:**
- An error shown under any form field is announced by TalkBack when it appears.
- A failed Shopping add whose text the user has since edited names the item it is about.
- A fast double tap on the Pantry add actions opens one add screen.

The same build then runs on the physical phone, including a TalkBack check and a fast double tap on the add button.

- KAN-38 (PF-NAV-002: Fast double tap on a Pantry add action opens the add screen twice), Low.

- **KAN-36** stays open and isn't part of this package. Package 3 is KAN-32 and KAN-36; Package 4 is KAN-27.

## What exists

- **`components/Input.tsx`:** renders `{error ? <Text style={styles.error}>{error}</Text> : null}`, with no role and no live region.
  - Used with `error` by login, register, confirm-email, add-item, the Pantry edit screen, the Shopping add field and the Shopping edit screen. All of them gain the announcement.
  - List-level errors already carry `accessibilityRole="alert"`: Pantry and Shopping list errors, `shopping-action-error`, add-item's load error, settings and `AuthGate`. `confirm-email.tsx` uses `accessibilityLiveRegion="polite"` for its sent message.
- **Shopping add:** `submit()` in `app/(tabs)/shopping.tsx` keeps `const submitted = name` and calls `setAddError(t(shoppingErrorKey(e)))` in its catch, whatever the field holds by then.
  - `onChangeText` clears the error, so the stale case needs an edit during the pending add.
  - Success already compares the field with `submitted` before clearing it.
- **Pantry add actions:** `app/(tabs)/index.tsx` calls `router.push('/add-item')` from the empty-state call to action (`onCtaPress`, testID `empty-state-cta`) and from the floating button (testID `pantry-fab-add`).
  - The rows use `const openEditor = useSingleOpen()` (KAN-33).
- **Tests:**
  - `tests/shopping-screen.test.cjs` has `renderAdd()` with a stubbed `Input`, plus add-error cases: rejected add, editing clears the error, text typed during a pending add is kept;
  - `tests/screens.test.cjs` loads the Pantry list with `routerStubs(push)`, which runs the real `useSingleOpen`, and has the KAN-33 row-tap case;
  - no test renders the real `Input`.
- **Device flows:** `.maestro/slice-1-1.yaml` first opens add with `tapOn: pantry-fab-add` on an empty pantry, then saves blank and asserts "Name is required." Add-screen testIDs: `add-item-name`, `add-item-save`, `add-item-cancel`.
- **Phone evidence from KAN-33/35:** `pantry-flow/.verification/evidence/kan-33-35/` in the main checkout. `pantryflow-test-arm64-v8a.apk` was built from `e8a6995` (SHA-256 `ad1786f6…f847`); its add actions are unguarded, so it's the red build for KAN-38.
- **Open follow-ups checked for this package:**
  - KAN-32 (PF-STATE-001) and KAN-36 (PF-PROMPT-001) touch neither `Input`, the Shopping add, nor the add pushes;
  - KAN-27 is tooling only.

## Global constraints

- **KAN-34:** native roles and live regions only, no web-only roles. No redesign of the forms.
- **KAN-37:** don't change the unchanged-text case: the error stays plain, exactly as today.
- **KAN-38 exclusions:** no navigation-framework change and no redesign of the Pantry screen.
- **Test first:** each fix has failing tests first, shown red on the current code.
- **Device scope:**
  - only the test APK (`com.pantryflow.test`), never `com.pantryflow.app`;
  - only local Supabase, through the loopback proxy and `adb reverse`, over USB ADB;
  - reserved fixture accounts, with exact cleanup.
- **TalkBack:** the owner turns it on and off on the phone. No `adb` change to accessibility settings.
- **No iOS or macOS CI.** VoiceOver isn't checked; KAN-34's device criterion asks for TalkBack.

## Review focus

1. **An error that appears while the field has focus is announced, and a changed error is announced again.** A live region on a view that only mounts with the error may not announce on some Android versions, and the phone runs Android 16. The device check decides; see Task 1, Step 4.
2. **No announcement and no layout change without an error.** The always-mounted live-region container must take no space and must not be focusable on its own.
3. **KAN-37 edge cases:**
   - an edit back to exactly the submitted text shows the plain error;
   - the named error clears on the next edit, like today's;
   - a household change still drops a pending add's error, as the existing "obsolete household" test pins.
4. **The add lock is shared with the row lock on the Pantry screen.** One lock per list screen: an add tap then a row tap opens one screen, and after returning, either opens normally.
5. **Auth forms:** login, register and confirm-email errors also go through `Input`, so their tests must stay green and their errors are now announced too.

## Rulings and risks carried into execution

- **Execution mode:** inline, as in the last package. Three small code tasks and a device task with the owner in the loop.
  - A Sonnet task review covers Tasks 1–3, and an Opus final review covers the branch.
- **An always-mounted live region, not a live region on the error text alone.** Android announces a live region when its content changes. A view that only mounts with the error may not count as a change.
  - Cost if wrong: Task 1, Step 4 switches to an explicit announcement after the device check.
- **The role stays on the error `Text`.** It's what the ticket names, and what iOS uses. It costs nothing on Android.
- **The named error reuses the `name: message` format.** No new translation keys (D5: new strings are English-only, and this adds none).
  - Cost if wrong: a wording change later, in one line.
- **One lock for rows and add actions.** Two different screens from one tap burst is the same defect class as KAN-33.
  - Cost if wrong: an add tap ignored for up to one second after a row navigation that silently failed. This is the same accepted limit as KAN-33.
- **Phone needed for Task 4 (about 1–1.5 hours, including the build):**
  - USB cable, Stay awake, `adb reverse` set again;
  - the owner present for the TalkBack step.
- **Jira:**
  - after the merge, KAN-34, KAN-37 and KAN-38 each move to Done only with the owner's approval;
  - KAN-36 stays open (owner, 2026-11-13).
