## Decisions for the owner

- **D1, KAN-85 item 1 (Cancel during the shopping add). Recommended: decline.**
  - Keeping Cancel enabled for the whole post-save phase is what guarantees nothing can lock the form (KAN-36). A shopping add that hangs would lock it again.
  - Pressing Cancel is an explicit choice to leave. Missing the notice afterwards is the same outcome as a late answer after Cancel, which is already accepted and tested.
  - Alternative: enable Cancel only while a dialog is open, and accept that a hanging add request locks the form.
- **D2, KAN-85 item 4 (only the new row during the re-read). Recommended: decline.**
  - It is unreachable through the UI, and the end state is correct.
  - Changing `PantryProvider` alone would make it diverge from `ShoppingProvider`; changing both touches tested KAN-32 logic for no user-visible gain.
  - Alternative: keep `loading` true until the re-read settles, in both providers.
- **D3, KAN-86 item 1. Recommended: rename the parameter to `_args`.** That keeps the uniform signature and marks the parameter as unused on purpose.
- **D4, Package 5 minors. Recommended: include P5-M4 and P5-M5; decline P5-M2.**
  - P5-M4 is one test. P5-M5 moves `announceError` to `lib/accessibility.ts`.
  - P5-M2: the restore error appears only after the session request fails, seconds after start. The phone check showed that such a late error is read correctly (pantry error at app start). It can't be triggered on a device.
  - Tracking: the three are listed in the KAN-86 closing comment. No new ticket.
- **D5, no phone session.** Only tests, docs, a Python rename and an import move change. CI's android job covers the rest.
