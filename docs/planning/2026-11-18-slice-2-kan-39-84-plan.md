**Constraints found:**
- A live region announces only when the content of a view that is already mounted changes. A whole-screen error view mounts in place of the spinner or the list, so a live region on it isn't reliable.
- The tabs stay mounted. A load error can appear while the user is on another tab. Announcing then would describe a screen that isn't visible.
- React Native 0.88 implements `AccessibilityInfo.announceForAccessibility` on Android as an `AccessibilityEvent.TYPE_ANNOUNCEMENT`. Android 16 deprecated that event type. Whether TalkBack 17.1 still speaks it on the owner's Android 16 phone is unverified. Task 2 checks it before the rollout.
- The test proxy can fail pantry reads (`/__test/fail-reads`) and shopping reads (`/__test/fail-shopping-reads`). So the phone can show the two list load errors. The sign-out, session restore, item detail and action errors are covered by unit tests only.

## Review focus

1. **Focus gating:** a load error that appears while another tab is visible is not announced then. It is announced once when the user opens that tab. Leaving and returning to a tab with an unchanged error announces it again; the user is entering a screen that shows an error.
2. **No double announcement:** an error in a live region is not also sent as an announcement. A changed `Input` error is announced by the live region only. `announceKey` speaks only when the text is unchanged.
3. **iOS unchanged:** no announcement call runs when `Platform.OS !== 'android'`. The alert roles stay.
4. **AuthGate:** it wraps the layouts, so it must not depend on a screen's focus state. It announces when its error appears.
5. **Layout and test IDs unchanged:** moving the live region into a shared component keeps every existing `testID`, style and Maestro selector.

**Interfaces (produced):**
- `InlineError({ message, style, testID }: { message: string | null; style?; testID? })`: an always-mounted `View` with `accessibilityLiveRegion="polite"` and `collapsable={false}`. When `message` is set, it contains an alert-role `Text`. `Input` renders its error through it, with the same output as today.
- `useErrorAnnouncement(message: string | null): void`: on Android only, calls `AccessibilityInfo.announceForAccessibility(message)` when `message` becomes non-null or changes. Used where no navigation focus exists, as in AuthGate.
- `useFocusedErrorAnnouncement(message: string | null): void`: on Android only, announces when `message` appears or changes while the screen is focused, and when the screen gains focus with `message` set. Built on `useFocusEffect` from `expo-router`, like `useSingleOpen`.
